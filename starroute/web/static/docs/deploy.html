Jumpgate Starroute

Two deploy strategies (one repo)

Keep one Git repository. Publish it two different ways depending on the audience.

1. Static host (recommended for players / GMs / demos)

Publish directory: starroute/web/static/

That folder already contains the map UI (app.html), docs (docs/), and preset JSON under presets/. Visitors open the site and switch packs in the toolbar. No Python on the server.

GitHub Pages (what this project uses for the public demo)

  • Prefer a GitHub Actions workflow in the repo (see .github/workflows/pages.yml) that uploads starroute/web/static/.
  • In the repository’s Pages settings, set the source to GitHub Actions (wording may vary; the durable idea is “deploy from the workflow,” not “deploy a branch folder by hand”).
  • After the workflow runs, the site is usually at https://<owner>.github.io/jumpgate_starroute/.
  • Useful paths: / (home), /app.html (map), /docs/, /docs/lore/ (wiki for the selected pack), /docs/help.html (click-? then click a control).

Cloudflare Pages (optional mirror)

  • Connect the same GitHub repo.
  • Build command: leave empty (nothing to compile for the static path).
  • Publish directory: starroute/web/static
  • Do not point Cloudflare at a Python runtime for this path. Regeneration stays on maintainer machines.

2. Builder / maintainer path (optional)

Clone the repo, create a virtualenv, install requirements.txt, then regenerate packs:

python -m starroute build-presets
# or: python scripts/build_presets.py

Use this when you change config/map_presets.json, swap catalogs, or retune jump knobs. Commit the updated JSON under data/presets/ and starroute/web/static/presets/, then let the static host pick them up on the next Pages deploy.

If data/raw NASA CSVs are missing, the builder falls back to the committed sample catalog in starroute/web/static/sample-systems.csv.

What not to do

  • Don’t require visitors to install Python to “see what it is.”
  • Don’t make Pages/Cloudflare run FastAPI for the public demo.
  • Don’t document vendor UIs step-by-click; document the publish directory and the Actions source.
