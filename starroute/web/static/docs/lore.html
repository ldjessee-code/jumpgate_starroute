Lore vault (static wiki)

Setting text lives as ordinary Markdown in the repo. GitHub Pages visitors browse a committed copy in the browser. There is no Wiki.js, Obsidian, Postgres, or edit-in-browser.

Open the lore viewer →

Layout

setting/                      source of truth (git clone)
  README.md                   tooling notes; not in the wiki index
  overview.md
  systems.md
  cultures.md
  history.md
  contributing.md

starroute/web/static/docs/lore/   what Pages actually serves
  index.html                  viewer
  index.json / index.js       page list
  pages/*.md                  copies of the vault
  marked.min.js               MIT Markdown renderer (vendored)

Add a page

  1. Create setting/your-topic.md. Subfolders are allowed (setting/cultures/kessari.md).
  2. Optional front matter: 
    ---
title: Your topic
order: 40
---
    Without it, the first # heading or the file name becomes the title.
  3. Regenerate the index. This walk is stdlib Python — missing NASA CSVs do not matter: 
    python -m starroute build-lore
# or: python scripts/build_lore.py
  4. Commit the new .md and the updated files under starroute/web/static/docs/lore/.

The public site only publishes starroute/web/static/. If you add a vault file and skip the index rebuild, Pages will not list it.

Try it locally

cd starroute/web/static
python -m http.server 8765

Then open http://127.0.0.1:8765/docs/lore/ (or .../docs/lore/index.html). Raw file:// is unreliable because the viewer fetches Markdown.

On GitHub Pages

After merge to main, the project site is typically:

  • Home — https://ldjessee-code.github.io/jumpgate_starroute/
  • Lore — .../jumpgate_starroute/docs/lore/

Links in the viewer are relative, so the /jumpgate_starroute/ base path does not need a special prefix.
